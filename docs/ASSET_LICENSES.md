The active model is now `web/public/models/tuki-v2y-visual.glb`; the prior `tuki-v2y.glb` and V2N GLB remain in `web/public/models/` as inactive backups. The two active preview images are `web/public/images/tuki-v2y-exterior.png` and `tuki-v2y-interior.png`. The original V2Y GLB and preview images were supplied in `TUKI_V2Y_WEB_MODELO_PRINCIPAL_FINAL.zip`; its migration document attributes the forearm/cabinet/door/board meshes to the associated owner-supplied V2Y STL package and the articulated hand to the supplied V2N web package. That package contains the final GLB and renders but not the underlying CAD/STL sources, so this record verifies package provenance and GLB structure, not a full independent CAD-to-mesh reconstruction. The owner describes V2Y as their AI-assisted CAD work; that declaration is not third-party authorization or legal certification. The targeted structural review found no external GLB resource URIs and no concrete third-party file dependency in the supplied original model/images. It does not prove absolute design independence. Historical Shapekit credits and CC BY-NC 4.0 notes below concern earlier prototypes and remain preserved; do not attribute current V2Y geometry to Shapekit without evidence.

This is an owner provenance declaration, not independent proof of every design decision and not authorization from a third party. ### Replacement of the V2K-derived enclosure subsystem

The superseded GLB contained these exact mesh nodes: `ACOPLE_MUNECA`, `RIOSTRA_IZQUIERDA`, `RIOSTRA_DERECHA`, `CARCASA_ANTEBRAZO`, `TAPA_ANTEBRAZO`, `MARCO_CAJON`, `CAJON_USB_C`, and `GUIA_CINCO_TENDONES`. These corresponded to the V2K-reused coupler, struts, forearm shell, lid, drawer frame/tray, and tendon guide identified by hash in the prior provenance investigation. Compatibility with the original Shapekit forearm is not evidence that those meshes copied its geometry; the legal/release concern was unresolved provenance of the V2K outputs and missing exact generator input.

Those meshes are absent from the active GLB. The replacement groups are `ForearmLeft`, `ForearmRight`, `WristCollar_PalmInterfacePending`, `ElectronicsBase`, `ServiceCover_USB_Pending`, and `ElectronicsCarrier`, under `FOREARM_V2N_ARM_V1`. A separate local parametric-CAD proposal generated these meshes without imported mesh input. Its CAD source and manufacturing STEP/STL outputs are intentionally excluded from this web-release staging; the public web package contains only the active GLB visualization. The local source evidence explains the generation process but does not by itself establish ownership, patent freedom, or legal independence of functional/mechanical ideas.

The already printed CAMA_00/CAMA_01 and hand parts were not modified. The wrist-to-palm pattern and USB-C cut-out remain intentionally unvalidated and are not presented as physically compatible.

### Evidence reviewed

- The supplied `TUKI_V2N_TODOS_STL_PARA_IMPRIMIR.zip` contains individual STL files and a validation report, but not the advertised assembly STEP, parametric build scripts, or web GLB. Its README states that the CAD was made for TUKI without importing Shapekit meshes; this is a provenance statement, not source evidence.
- The separate web migration ZIP contains the GLB, preview images, rig and integration notes, but no CAD generator or STEP source.
- A reproducible GLB/STL mesh comparison matched all 277,484 triangles in the named V2N mesh entries to the corresponding supplied V2N STL parts (triangle vertices compared after rounding to 0.01 mm). The GLB embeds its buffer and has no external resource URIs. This establishes the immediate GLB-to-STL mesh relationship, not how those STL meshes were designed.
- All fourteen finger STL files in V2N are byte-identical to their matching V2J outputs. The included V2J `build_tuki_v2j.py` constructs geometry through CadQuery operations and does not load mesh files as inputs. The V2K ZIP includes a byte-identical copy as `origen_v2j_mano.py`. This confirms internal TUKI V2J-to-V2N reuse for the phalanges; it does not establish independence of all design decisions.
- V2N's coupler, left/right struts, forearm shell, lid, drawer frame/tray and tendon guide match V2K outputs by SHA-256. V2K's `build_v2k.py` reads `build_tuki_v2j.py` and `build_tuki_v2_engineering.py` from absolute project paths. The second exact input is absent from the package. The ZIP does include `origen_v2_antebrazo.py`, an alternate V2 CAD source, but no evidence establishes that it is byte- or geometry-equivalent to the missing input. CadQuery is not installed in this environment, so no source regeneration was run.
- The V2N V2M diagonal rack, V2N palm-with-thumb-passage, and individual horn-pulley source scripts were not found. The supplied A1 bed arranger only rotates/translates and packs existing meshes. No V2N master STEP or STL-to-GLB export script was found.
- Both image hashes match the migration ZIP's SHA-256 manifest. The PNGs contain no authorship, EXIF, camera, or render metadata. Their appearance is consistent with the GLB, but no render script or source project proves they were rasterized directly from this exact GLB.
- The latest `TUKI_A1_MINI_STL_REVISADOS_ORIENTACION_TORNILLOS.zip` says its forearm shell and lid are the original Shapekit parts already printed, unmodified. It marks the V2N wrist coupler/struts as compatibility-pending with that original Shapekit housing. This documents a mixed physical integration plan, not proof that V2N itself contains copied Shapekit mesh geometry.
- A geometric fingerprint comparison found no substantial triangle-mesh match between the inspected V2N hand/case meshes and cached original Shapekit STL references. This heuristic can rule out neither copied design intent nor derivative mechanical solutions and is not a legal independence test.
- A targeted facet comparison was repeated for the old V2N palm, rack, wrist coupler, struts, tendon guide, forearm shell, lid, drawer frame/tray, and pulley against available cached Shapekit references. No identical triangle facets were detected in the tested pairs. The comparison is sensitive to triangulation and transforms and cannot rule out geometry or design derivation. The old forearm/case meshes listed above are no longer in the active model.
- The new V2N/A1 Mini arm source has no external STL/STEP/OBJ/GLB import. Its own generated meshes replaced the old shell/coupler/struts/lid/drawer/guide in the website GLB. The new exterior/interior preview PNGs were recaptured from the running viewer with that GLB; retired previews remain local-only backups outside the release.
- The current and historical migration ZIPs are duplicates by file hash. Local Git has one initial commit; its available dangling blobs do not contain the missing CAD sources. The full per-file inventory and search limits are recorded in `docs/V2N_MANIFIESTO_PROCEDENCIA.md`.

### Provenance distinctions and unresolved items

The owner declares that retained V2N geometry was developed for the project with AI-assisted parametric CAD. Available artifacts substantiate the previous GLB's correspondence to supplied V2N STL outputs, internal V2J reuse for the fingers, and V2K reuse for enclosure parts that are now removed. The original V2N generator and V2K's exact engineering input were not found, so the complete historical chain cannot be independently reconstructed. The replacement arm has a present, reproducible parametric source. The owner has directed staging of the current GLB and previews for release; no concrete third-party material or required third-party permission was identified in this review. This records the owner's release direction and the evidence examined; it is not an external rights grant or legal certification.

Therefore these statements remain distinct:

1. The old forearm/case group with unclear V2K source has been removed from the active GLB and replaced by a new parametric arm whose source is available. No Shapekit mesh import is present in that new generator.
2. For the retained V2N hand/rack/pulley meshes, the inspected source chains and geometric fingerprint tests did not show direct Shapekit STL imports or identical tested facets. The unavailable full V2N CAD source means this is not proof of mechanical independence or absence of derivative design choices.
3. The prior plan physically integrated some V2N components with an original Shapekit forearm; that physical compatibility statement is separate from whether the former web meshes copied Shapekit geometry. A separate V2P source explicitly loads Shapekit V3 forearm and lid STL files as references; V2P is not used by the web model.
4. The new arm's parametric geometry has a documented source chain. The owner declares the retained V2N model was developed by the project team and directs preparation for redistribution. No Shapekit mesh import, identical tested facets, or external third-party asset was found in the reviewed GLB/images. If later evidence establishes that a retained component adapts Shapekit's work, CC BY-NC 4.0 permits sharing and adaptation under its attribution, change-notice, and NonCommercial terms; the CV-linked portfolio's NonCommercial classification would then need a fact-specific assessment.
