# Asset licenses and provenance

## TUKI V2N + V4 R1 web assembly (2026-11-26)

The active file `web/public/models/tuki-v2n-v4-r1.glb` was supplied inside `TUKI_R1_ENSAMBLE_VISUAL_COMPLETO.zip`. Its generation record identifies three inputs: the owner-supplied V2N hand GLB from the web migration package, the 24-solid V4 R1 assembly STEP from `TUKI_V4_FINAL_A1_MINI.zip`, and `SG90_DETALLADO_COLOR.glb` from the owner-provided electronics reference package. The current GLB SHA-256 is `55c746ef29692cee5f396ea87b913e4be105c60d591f93ac3925af380f5caeb3`.

The R1 parts were triangulated from the supplied CAD assembly STEP in assembly coordinates. The hand source is the V2N web migration GLB, whose geometry-to-STL evidence and owner provenance statement are recorded in the historical V2N review below. The SG90 reference geometry is generated by the package parametric CadQuery source from nominal reference dimensions; no external servo mesh file is imported. The R1 model process embeds the three inputs into one GLB. The targeted review found no external resource URI or identifiable third-party mesh dependency in the assembled GLB and reviewed generation record. That is a finding about the inspected files, not certification of mechanical independence, ownership, physical fit, or all design rights.

The GLB has one embedded binary buffer, no external images, 24 V4 R1 solid meshes, five nominal SG90 groups, 14 hand joints and five `CLOSE_*` clips. The root matrix converts millimetres to metres. It is a web visualization only; the SG90s are nominal references, and the V2N palm-to-R1 wrist interface is unverified. Generic electronics references from the source packages are not included in the active model because the exact devices have not been measured.

The browser preview images `web/public/images/tuki-v4-r1-exterior.png` and `tuki-v4-r1-interior.png` are captures of the active GLB in the local web viewer. They do not independently add model geometry or establish fit.

## Camera Tracking dependency (2026-11-26)

Studio uses the pinned npm package `@mediapipe/tasks-vision` version `1.2.3`. The MediaPipe source project is Apache-2.0 licensed. The Hand Landmarker task model is fetched at activation from Google's official `hand_landmarker/float16/1` model URL; Google's Hand Tracking model card states Apache License 2.0. The worker's WASM runtime is fetched from the matching pinned jsDelivr npm package URL. Model and WASM binaries are not checked into the repository. See the [Hand Landmarker Web guide](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker?tab=Web), [MediaPipe model card](https://storage.googleapis.com/mediapipe-assets/Model%20Card%20Hand%20Tracking%20%28Lite_Full%29%20with%20Fairness%20Oct%202021.pdf), and [MediaPipe repository license](https://github.com/google-ai-edge/mediapipe/blob/master/LICENSE). Video frames are processed locally and are not uploaded by TUKI; MediaPipe's published privacy notice says it sends task usage/performance metrics to Google. The application discloses this in the camera panel. This record identifies the SDK/model sources and stated licenses; it is not a legal certification.

### Evidence reviewed

- The supplied `TUKI_V2N_TODOS_STL_PARA_IMPRIMIR.zip` contains individual STL files and a validation report, but not the advertised assembly STEP, parametric build scripts, or web GLB. Its README states that the CAD was made for TUKI without importing Shapekit meshes; this is a provenance statement, not source evidence.
- The separate web migration ZIP contains the GLB, preview images, rig and integration notes, but no CAD generator or STEP source.
- A reproducible GLB/STL mesh comparison matched all 277,484 triangles in the named V2N mesh entries to the corresponding supplied V2N STL parts (triangle vertices compared after rounding to 0.01 mm). The GLB embeds its buffer and has no external resource URIs. This establishes the immediate GLB-to-STL mesh relationship, not how those STL meshes were designed.
- All fourteen finger STL files in V2N are byte-identical to their matching V2J outputs. The included V2J `build_tuki_v2j.py` constructs geometry through CadQuery operations and does not load mesh files as inputs. The V2K ZIP includes a byte-identical copy as `origen_v2j_mano.py`. This confirms internal TUKI V2J-to-V2N reuse for the phalanges; it does not establish independence of all design decisions.
- V2N's coupler, left/right struts, forearm shell, lid, drawer frame/tray and tendon guide match V2K outputs by SHA-256. V2K's `build_v2k.py` reads `build_tuki_v2j.py` and `build_tuki_v2_engineering.py` from absolute project paths. The second exact input is absent from the package. The ZIP does include `origen_v2_antebrazo.py`, an alternate V2 CAD source, but no evidence establishes that it is byte- or geometry-equivalent to the missing input. CadQuery is not installed in this environment, so no source regeneration was run.
- The V2N V2M diagonal rack, V2N palm-with-thumb-passage, and individual horn-pulley source scripts were not found. The supplied A1 bed arranger only rotates/translates and packs existing meshes. No V2N master STEP or STL-to-GLB export script was found.
- Both image hashes match the migration ZIP's SHA-256 manifest. The PNGs contain no authorship, EXIF, camera, or render metadata. Their appearance is consistent with the GLB, but no render script or source project proves they were rasterized directly from this exact GLB.
- The latest `TUKI_A1_MINI_STL_REVISADOS_ORIENTACION_TORNILLOS.zip` says its forearm shell and lid are the original Shapekit parts already printed, unmodified. It marks the V2N wrist coupler/struts as compatibility-pending with that original Shapekit housing. This documents a mixed physical integration plan, not proof that V2N itself contains copied Shapekit mesh geometry.
- A geometric fingerprint comparison found no substantial triangle-mesh match between the inspected V2N hand/case meshes and cached original Shapekit STL references. This heuristic can rule out neither copied design intent nor derivative mechanical solutions and is not a legal independence test.
- A targeted facet comparison was repeated for the old V2N palm, rack, wrist coupler, struts, tendon guide, forearm shell, lid, drawer frame/tray, and pulley against available cached Shapekit references. No identical triangle facets were detected in the tested pairs. The comparison is sensitive to triangulation and transforms and cannot rule out geometry or design derivation. The old forearm/case meshes listed above are no longer in the active model.
- The new V2N/A1 Mini arm source has no external STL/STEP/OBJ/GLB import. Its own generated meshes replaced the old shell/coupler/struts/lid/drawer/guide in the website GLB. The new exterior/interior preview PNGs were recaptured from the running viewer with that GLB; retired previews remain local-only backups outside the release.
- The current and historical migration ZIPs are duplicates by file hash. Local Git has one initial commit; its available dangling blobs do not contain the missing CAD sources. The full per-file inventory and search limits are recorded in `docs/V2N_MANIFIESTO_PROCEDENCIA.md`.

4. The new arm's parametric geometry has a documented source chain. The owner declares the retained V2N model was developed by the project team and directs preparation for redistribution.
